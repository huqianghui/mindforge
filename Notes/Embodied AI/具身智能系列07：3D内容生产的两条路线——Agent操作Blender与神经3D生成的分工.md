前几篇讲的 TRELLIS、Gaussian Splatting、Marble 都是"神经网络直接生成 3D"。但 2026 年 9 月 OpenAI 发布 GPT-6 Astra 后，另一条路线成了现实：**通用 Agent 操作传统 3D 工具**——官方 demo 里 Astra 在 Blender 里建出一栋房子的模型，再导入 Unreal Engine 5 变成可行走场景；它在 BenchCAD（看多视角渲染图、写 CAD 代码重建 3D 物体）上拿到 95.9%。这两条路线是什么关系？本篇对比。

关于 Astra + Blender 这条链路本身的实操（工具选型、MCP 安装、实战案例），vault 里已有独立系列：[Blender 系列 01：为什么是 Blender——GPT-6-astra 发布演示的 3D 工具选型与 Unreal Engine 对比](../tool/3D-blender/Blender系列01：为什么是Blender——GPT-6-astra发布演示的3D工具选型与Unreal%20Engine对比.md)。本篇聚焦它与神经 3D 生成的路线对比。

## 一、本质区别："指挥工具造出 3D" vs "直接生成 3D"

**Astra + Blender**：语言模型看图或读需求，理解后写 Blender Python 脚本（或操作 GUI），让 Blender 这个**确定性引擎**去构造几何，然后渲染出来自己看一眼，不对再改。3D 本身不是模型"生成"的，是模型"指挥工具"造出来的。

**TRELLIS / Splatting / Marble**：神经网络从图像直接输出 3D 表示（mesh、splats、结构化潜变量），中间没有符号化过程，秒级出结果。

如果你读过[系列02](具身智能系列02：VLA输出架构演进——从动作token到扩散动作头.md)，会认出这个格局：**这几乎就是"structured output 派 vs 连续生成头派"之争在更高层的放大版**——只是 structured output 从 JSON 变成了 Python 代码，执行器从解析器变成了 Blender；连续生成头从动作扩散头变成了 3D 生成模型。同一对权衡（离散符号 + 确定性执行 vs 连续分布 + 一次前向）在不同尺度上反复出现。

## 二、逐项对比

| 维度 | GPT-6 Astra + Blender / UE5 | TRELLIS / Splatting / Marble |
|---|---|---|
| 输出性质 | 参数化、程序化：精确尺寸、可编辑、可版本管理、可直接出加工图 | 神经表示：视觉逼真，但尺寸是近似的、不可参数化编辑，导出 mesh 后拓扑往往很乱 |
| 对真实世界的保真 | 靠模型"理解后重建"，规则几何很好；复杂有机形状、材质细节要反复迭代 | 重建类（Splatting）对真实场景外观保真最高；生成类（TRELLIS）会"合理地脑补"看不到的背面 |
| 速度与成本 | 分钟到小时级，agent 循环消耗大量 token，一个复杂场景可能几十美元 | 秒级，单次推理成本几乎可忽略 |
| 可验证、可审计 | 每一步都是代码：可复现、可 diff、可人工审核——天然能放进责任结构 | 黑盒生成，结果对不对只能靠看 |
| 处理复杂度 | 能编排整条管线：建模 → 材质 → 物理属性 → 导入引擎 → 交互逻辑，能处理约束和规则 | 单一模型做单一环节（一个物体、一个场景的静态几何） |
| 空间理解来源 | 模型无 3D 原生感知，靠"写代码 → 渲染 → 看图 → 修正"闭环逼近（BenchCAD 95.9% 说明闭环已很有效） | 模型内部直接学到 3D 先验，一次前向就有空间结构 |
| 动态与物理 | 接上 UE5 / Blender 物理引擎后天然有物理——即[系列04](具身智能系列04：世界模型不是一种架构——像素、潜空间、显式3D与物理方程四条实现路线.md)的"物理方程路线" | 本身是静态的，动态要另接引擎或世界模型 |
| 运行位置 | 云端大模型，高延迟 | 可端侧或近端部署，可实时 |

## 三、各自的位置：离线生产 vs 运行时感知

**Astra + Blender 的主场在离线的生产环节**：设计阶段的概念可视化、数字孪生搭建、仿真环境构建、把一堆资产组装成带物理规则的可交互场景。它做的是"**内容生产工具链的自动化**"——以前搭一个机器人工作单元的仿真环境要工程师干一周，现在 Agent 操作工具几小时搞定。这正是"自动化工程体系被 AI 重写"的具体形态之一。但它和机器人**运行时**无关：扫地机在客厅里以每秒几十帧感知世界，不可能每帧调一次云端大模型去写 Blender 脚本。

**TRELLIS、Splatting 这类神经模型的主场在运行时感知和批量生产**：机器人现场看到一个陌生物体，3 秒内得到它的三维形状用于抓取规划；从几张照片快速重建现场；批量为仿真生成上万个物体资产。它做的是"**感知能力本身**"。

所以两者不是竞争关系，最合理的组合是**分层**：神经 3D 模型负责快速产出原材料（单个物体的 3D、现场的重建），Agent 负责把原材料组装成带规则、带物理、可验证的完整世界。这其实就是 World Labs 收购 SceniX 想拼的那个东西（[系列04](具身智能系列04：世界模型不是一种架构——像素、潜空间、显式3D与物理方程四条实现路线.md)），只是用"通用 Agent + 成熟工具"的方式而不是"专用生成模型 + 专用仿真"的方式实现。

一个对具身智能很实际的用法：用 Agent 在 Blender / UE5 里基于真实户型数据**批量生成家庭仿真场景**，测试移动机器人的避障与导航策略——这正是[系列01](具身智能系列01：全景与技术路线——从LLM、Agent、RAG到物理世界闭环.md)里"把真机数据昂贵转化为仿真规模化试错"的落地形态。

## 四、趋势判断：短板正在被工程手段绕过

"3D / 空间拓扑理解是大模型的明显短板"这个行业判断，针对的是模型的**原生空间感知**——不借助工具、不迭代、一眼看出空间关系。这个判断今天依然成立。但 Astra 在 BenchCAD 上 95.9% 说明：**借助工具和闭环验证（写代码 → 渲染 → 看图 → 修正），短板正在被工程手段绕过**——这和"LLM 不会算数但会调计算器"是同一个故事。

不过绕过是有边界的：有机形状、真实材质、实时性、端侧运行，仍然是神经 3D 模型不可替代的领域。两条路线会长期并存，分界线就是上面那张表。

> 边界说明：Astra 的 Blender demo 官方只给了展示，具体是纯脚本驱动还是含 GUI 操作、需要多少轮迭代、成本多少均未公开，本文关于其能力边界的描述是基于公开材料的推断。
