# Memory Review Skill

审查 Auto Memory 系统的健康状态，识别需要提权、更新或删除的条目。

## 执行流程

### Step 1：读取当前状态

读取以下文件：
- `MEMORY.md`（索引文件）
- 所有 `memory/*.md` 主题文件
- `AGENTS.md`（检查已提权的规则）
- `.Codex/rules/*.md`（检查已分流的规则）

### Step 2：逐条审计

对每条 Memory 条目，判断其类型和当前状态：

| 审计维度 | 检查内容 |
|---------|---------|
| **类型错配** | 是否是行为规则（"必须/禁止"）但只存在于 Memory？→ 建议提权到 AGENTS.md 或 Rules |
| **已重复** | AGENTS.md / Rules 中是否已有同等规则？→ 建议从 Memory 删除或标注"已提权" |
| **已过时** | 内容是否与当前项目状态矛盾？→ 建议更新或删除 |
| **待验证** | 首次观察到的偏好是否已被后续行为确认？→ 确认则保留，否则标记 |

### Step 3：生成审计报告

输出格式：

```
## Memory Review Report — {date}

### 需要提权（Memory → AGENTS.md/Rules）
- [ ] {条目} — 原因：{为什么需要提权}

### 需要更新
- [ ] {条目} — 原因：{哪里过时了}

### 需要删除
- [ ] {条目} — 原因：{为什么应该删除}

### 状态良好
- {条目} — 类型正确，内容有效

### AGENTS.md 体积检查
- 当前行数：{N} 行（建议上限 100 行，超出部分应分流到 .Codex/rules/）
```

### Step 4：用户确认后执行

**不要自动执行任何修改。** 输出报告后等待用户逐条确认，然后：
- 提权：将规则写入 AGENTS.md 或 `.Codex/rules/` 对应文件
- 更新：修改 Memory 文件内容
- 删除：移除 Memory 文件并更新 MEMORY.md 索引
