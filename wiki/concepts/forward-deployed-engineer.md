# FDE（Forward Deployed Engineer）：客户系统的外部调节器

## 摘要

FDE（前线部署工程师）——被部署到客户前线，用工程能力将平台价值翻译为客户业务价值的人；CSA（Cloud Solution Architect）本质上是 Microsoft 生态中的 FDE。AI Agent 时代 FDE 面临商业模式悖论：若终极目标是"教会客户用 AI 自己做"，教会之后还剩什么？本页的核心解答：**FDE 不是老师（一次性知识转移），而是客户业务系统的外部调节器（Regulator）**——客户系统是被调节对象，平台是执行器，FDE 感知偏差、设计修正、形成反馈闭环；只要扰动不停止（市场、技术、业务持续变化），调节就不会"完成"（理论依据见 [[requisite-variety]]）。个人复利来自三资产乘法：跨客户模式库（诊断速度）× Harness 资产库（交付效率）× 信任资本（商业转化），任何一项为零整体归零。

## Claims

### Claim: FDE 是调节器不是老师——"教会客户"是错误框架，调节关系不会"教完"

- **来源**：[[FDE职业进化论——AI时代前线部署工程师的个人突围与团队重构]]
- **首次出现**：2026-05-30
- **最近更新**：2026-08-04
- **置信度**：0.75
- **状态**：active

> 老师的价值在"我知道你不知道的"——学生学会即归零；调节器的价值在"持续感知和修正系统偏差"——系统在运行、环境在变化，需求就不消失。四个不可能"教完"的维度：① 前沿永远在移动（模型每季度升级，旧 Harness 变死重需重估）；② 跨域视角不可内部复制（客户团队只见自己业务域）；③ Regulation 需持续适应（新扰动持续涌入）；④ 信任的"利息"创造新需求（深度信任使客户在战略早期就邀请参与）。类比：FDE 是客户技术系统的"外部免疫系统补充"——免疫系统不会"完成"，因为病原体在持续进化。

### Claim: 个人复利 = 模式库 × Harness 库 × 信任资本，乘法关系任何一项为零整体归零

- **来源**：[[FDE职业进化论——AI时代前线部署工程师的个人突围与团队重构]]
- **首次出现**：2026-05-30
- **最近更新**：2026-08-04
- **置信度**：0.75
- **状态**：active

> 三资产：① 跨客户模式库——把 20 个客户的实施经验编译为可迁移的架构决策 Meta-Pattern（PKC 对 FDE 的意义正在于此），检验标准是"面对新客户第一次会议就能说出'我见过这种情况'"；② Harness 资产库——行业级 CLAUDE.md 模板、陷阱清单、Spec 模板、验证脚手架、Skill 库，新项目启动从 2 周降到 2 天；③ 信任资本——不可转让、随时间累积、有利息（客户主动找你）、可贬值（一次重大失误消耗多年积累）。乘法关系：模式库丰富但没 Harness → 诊断快交付慢；Harness 完善但模式单一 → 换行业归零；前两项强但没信任 → 没人给机会证明。

### Claim: 可持续商业模式是伙伴制不是项目制——卖"持续的 Regulation 能力"而非"知识转移"

- **来源**：[[FDE职业进化论——AI时代前线部署工程师的个人突围与团队重构]]
- **首次出现**：2026-05-30
- **最近更新**：2026-08-04
- **置信度**：0.7
- **状态**：active

> 三种商业模式：项目制（卖人天，做完就走）、产品制（FDE 型工作难产品化——每个客户的 Ontology 都是定制的）、伙伴制（按价值收费、与客户共同成长）。客户持续付费的三个理由：前沿差（FDE 永远比客户快 6-12 个月，且随 AI 加速扩大而非缩小）、Regulation 需持续维护（模型升级→约束重估，业务变化→新调节机制）、跨域授粉（A 行业的方案恰是 B 行业急需但不知道存在的）。LTV 公式：初始实施收入是一次性的，持续进化服务（前沿引入 + Regulation 维护 + 跨域授粉 + 能力升级）是经常性的，信任加深后后者远大于前者。

### Claim: 长期策略——价值锚从"操作知识"（会被模型吞噬）迁移到三种元能力

- **来源**：[[FDE职业进化论——AI时代前线部署工程师的个人突围与团队重构]]
- **首次出现**：2026-05-30
- **最近更新**：2026-08-04
- **置信度**：0.75
- **状态**：active

> Bitter Lesson 对 FDE 的警告：特定平台的操作知识（"怎么配 Azure Cognitive Search"）和标准化架构模板会被更强的模型吸收；不被吞噬的是三种元能力——问题定义（"这个客户的真正痛点是什么"，需要理解后果）、约束设计（"该约束什么、放开什么"，需要商业判断）、跨域迁移（"A 行业模式能否用到 B"，需要类比推理 + 后果评估）。AI Native FDE 公式：认知主权 × Harness Engineering × One Person Team——三者也是乘法关系。

### Claim: AI Native FDE 团队 = 2-3 人精英组 + AI Agent 编队，协调通过 Spec 不通过会议

- **来源**：[[FDE职业进化论——AI时代前线部署工程师的个人突围与团队重构]]
- **首次出现**：2026-05-30
- **最近更新**：2026-08-04
- **置信度**：0.7
- **状态**：active

> 传统 8 人团队按技术层分工（前端/后端/数据/DevOps），协调成本高；AI Native 团队 2-3 个 AI-Augmented Senior FDE 各负责一个客户域端到端，AI Agent 覆盖技术层执行，协调通过 Spec + Contract。配套条件：个人 PKC 汇入团队级知识飞轮（知识必须"编译"才是资产；Harness 是共享 IP 不是个人收藏；新人通过 Harness 快速达到资深质量线）。大部分团队卡在 Mitchell Hashimoto 六步的第 1-2 步——从问答式到委托式是认知模式跃迁，**不教工具，教范式**。
