# VLA（Vision-Language-Action Model）

## 摘要

VLA（Vision-Language-Action）模型在 VLM 骨干上接动作输出，让同一个模型看图、听指令、直接出动作——**把"动作"当成和图像、语言并列的一种模态来预测**。代表：Google RT-2、OpenVLA、Physical Intelligence π 系列、NVIDIA GR00T、微软 Rho-alpha。各家共同点是复用 VLM 的视觉语言理解，差异在数据来源（遥操作/仿真/人类视频）、模态覆盖（是否加触觉/力）、跨形态迁移成本三处。

理解 VLA 架构的主线是**输出方式的两代演进**：第一代把动作离散化成 token（RT-2/OpenVLA，2023–2024），第二代用独立的连续动作头（扩散/flow matching，π0 起）——转向的根本原因是动作输出的问题形状（连续、高频、多峰、维度耦合）与 structured output 的收益模型冲突。π 系列（openpi 开源）是把原理对到真实模型演进的最佳样本。

## Claims

### Claim: 动作输出从离散 token 转向连续动作头的四个原因——精度平滑性、频率延迟、多峰分布（最本质）、维度间耦合；主流系统仍是分层的

- **来源**：[[VLA系列01：VLA输出架构演进——从动作token到扩散动作头]]
- **首次出现**：2026-09-17
- **最近更新**：2026-09-25
- **置信度**：0.7
- **状态**：active

> Computer use 与机器人控制的输出分界：低频秒级/高频 10–50Hz、离散命令/连续控制信号（本身就是执行）、答案通常唯一/常常多解（多峰）、容错高/毫米级偏差即失败、可重试/不可撤销。两者不对立——主流 VLA 是分层的：高层任务规划（VLM 做任务分解，低频离散决策，完全可用 structured output）+ 低层动作策略（连续动作头译成高频控制信号）；planner/executor 结构依然成立，只是 executor 从确定性代码换成概率性控制模型。

### Claim: π0 证明 VLM 知识可以接到连续控制上——双专家共享 self-attention 交互 + 流匹配整块生成；但权重分离 ≠ 梯度隔离，动作损失仍侵蚀 VLM 主干（KI 因此而生）

- **来源**：[[VLA系列04：π0、FAST与Hi Robot——流匹配动作专家、频域动作分词与分层交互]]、[[VLA系列05：π0.5、知识绝缘与实时分块——开放世界泛化、梯度隔离与异步执行]]
- **首次出现**：2026-09-21
- **最近更新**：2026-09-25
- **置信度**：0.75
- **状态**：active

> 官方论文核对后的精确表述：π0 两组专家权重（VLM 3B + 动作专家 300M 刻意做小）通过共享 self-attention 交互（非固定拼接+MLP——那是带噪动作与 flow timestep 的输入适配器；也非稀疏 MoE——按模态静态分配权重，无 learned router）；整块动作（H=50）经多步 flow matching 数值积分**联合**生成，与 π0-FAST 的自回归解码相对。Knowledge Insulation 的解法：梯度隔离 + 双目标单阶段协同训练——训练吃自回归的快、部署吃流匹配的快。

### Claim: FAST 证明离散路线的瓶颈在分词而非离散本身——离散/连续是分工不是替代

- **来源**：[[VLA系列04：π0、FAST与Hi Robot——流匹配动作专家、频域动作分词与分层交互]]
- **首次出现**：2026-09-21
- **最近更新**：2026-09-25
- **置信度**：0.75
- **状态**：active

> 朴素离散化卡在逐维取整的分词上；FAST 用 DCT+BPE 频域压缩（系数缩放取整使不显著系数归零再 BPE），压缩后自回归训练快 5 倍、精度与流匹配相当——但推理延迟大 7 倍（2B 主干串行解码 30–60 token）。π0.5 把两条路线串联："离散 token 预训练 + 流匹配后训练"，各取所长。这修正了"structured output 在物理控制域不成立"的论断强度：离散可行，但代价在推理侧。

### Claim: π0.5 的开放世界泛化靠数据组合而非架构魔法——97.6% 预训练数据来自非目标平台，环境数 3→104 性能单调上升

- **来源**：[[VLA系列05：π0.5、知识绝缘与实时分块——开放世界泛化、梯度隔离与异步执行]]
- **首次出现**：2026-09-21
- **最近更新**：2026-09-25
- **置信度**：0.75
- **状态**：active

> "没见过的房子里干活"的实验支撑：去掉跨平台数据（WD）则分布外指令遵循崩坏。π0.6/π*0.6 的 RECAP 转向真机经验 RL——与软件 Agent 的 APO→SFT→RL 阶梯平行（先把模仿/监督做扎实再引入强化信号）；注意 RECAP 的"从经验学习"含人工纠正+离线迭代，非部署中实时更新。

### Claim: 分层是能力结构，不必然是部署结构——Hi Robot 双模型分层 vs π0.5 同权重分层

- **来源**：[[VLA系列04：π0、FAST与Hi Robot——流匹配动作专家、频域动作分词与分层交互]]、[[机器人系统系列03：角色与实现的分离——七个功能角色、合并拆分光谱与扫地机器人的演进路径]]
- **首次出现**：2026-09-21
- **最近更新**：2026-09-25
- **置信度**：0.7
- **状态**：active

> Hi Robot 用同一 VLM 底座两种微调实现 System 2（约 1s 或收到语言反馈触发，实时语言反馈成为一等输入）/System 1（高频出块）双模型分层；π0.5 把同样的分层做在同一组权重里（统一分层推理）。"角色是接口、模型是实现"框架的最佳实例对：角色分离≠模型分离——VLA 内嵌世界模型有三种融合模式（UniPi 想象后动/WorldVLA 联合训练/网络内规划），一组权重可以同时扮演多个角色。

### Claim: 评估 VLA 声明的维度清单——新环境/新物体/新技能是三件事，成功率必须挂实验设置，三个频率口径必须分开

- **来源**：[[VLA系列05：π0.5、知识绝缘与实时分块——开放世界泛化、梯度隔离与异步执行]]、[[VLA系列04：π0、FAST与Hi Robot——流匹配动作专家、频域动作分词与分层交互]]
- **首次出现**：2026-09-21
- **最近更新**：2026-09-25
- **置信度**：0.75
- **状态**：active

> 评估任何 VLA 声明至少分开问：新环境/新物体/新技能泛化（π0.5 未见住宅实验≠任意家庭任意任务）；成功率挂什么任务与设置；错误恢复与人工介入率；数据成本（多少小时遥操作/多少环境）。频率口径纠错（π0 附录 D 一手数字）：动作块生成延迟（100/750ms，本机 73ms=14+32+27）≠ 最大串行推理调用速率 ≠ 控制执行频率（50Hz 级）≠ 重规划频率（20Hz 平台 16 步重规划 ≈1.25Hz，"实验设置非架构上限"）。常见误读纠正表 6 条（见 VLA04 第四节）可直接作反例证据。

### Claim: VLA 选型看场景而非排名——GR00T/π0/OpenVLA 定位本质不同

- **首次出现**：2026-09-20
- **最近更新**：2026-09-25
- **置信度**：0.65

> 人形/Isaac 生态/快速 POC 选 GR00T N1.7（cross-embodiment 设计：relative end-effector action space、state/action 132 维、horizon 40；Policy Server 形态嵌控制回路，TensorRT 加速 H100 上 11.7→35.9Hz——无 NIM 是产品形态差异非能力缺陷）；研究 flow policy 选 π0；改架构做 baseline 选 OpenVLA；机械臂先 benchmark 再定。单篇咨询讨论成文，无自身实测。
