# Recursive Self-Improvement（递归自我改进）

## 摘要

RSI 指系统把经验和反馈变成**对自身的持久修改**，并且这些修改会影响**之后的改进怎么产生、怎么评估、怎么被选中**。可以把 agent 写成状态 $S_t = (M_t, H_t, D_t, T_t)$——模型、harness、数据系统、训练系统四个可改进对象——再加一个改进机制 $I_t$：$S_{t+1} = I_t(S_t, \text{经验与反馈})$。$I_t$ 由人写定、保持不变时，系统是在固定机制里持续优化；只有 $I_t$ 本身被持久修改、且修改后的机制实际支配后续轮次，递归才发生在改进机制上。

由此两条推论：权重更新不是 agent 自我改进的唯一途径（skill、工具、工作流、记忆都能承载学习结果）；权重更新也不自动意味着递归（按人定配方一直训练，改进机制可能从未变化）。读任何 self-improving 工作都先问五件事：改的是什么、凭什么改、改动存在哪里、下一轮继承什么、用什么实验能推翻它的提升主张。

## Claims

### Claim: 三种"变好"要分开——任务内修正、持久状态改进、改进机制本身被改进，只有第三种才是递归

- **来源**：[[RSI系列00：递归自我改进总览]]
- **首次出现**：2026-10-21
- **最近更新**：2026-10-24
- **置信度**：0.75
- **状态**：active

> 数据分析 agent 例：修正 SQL 重跑得到正确报告、经验不进后续运行 = 任务内修正；从多次失败提炼"关联前先查键唯一性"写进 skill、下次继续用 = 持久状态改进（权重不变也算持续收益）；优化器发现"只从失败日志追加规则会越积越冗余"，把优化策略本身改为比较成败轨迹、每次少改、记录被否决方案，且新策略实际支配后续轮次 = 改进机制递归。The Last AI Built by Humans 区分**结构证据**（机制确实被修改并被下一轮使用）与**效果证据**（修改后的机制在可比预算下产生更强后继系统），两者需分别验证，有前者不等于有后者。

### Claim: 两套五级分级编号含义不同——阿里综述按"能否提出/实施/验证/改写机制/跨领域"，Last AI 按"接管了生命周期里哪些决策"

- **来源**：[[RSI系列00：递归自我改进总览]]
- **首次出现**：2026-10-21
- **最近更新**：2026-10-24
- **置信度**：0.75
- **状态**：active

> 阿里 The Path to Recursive Self-Improving Agents：L1 人工改进 → L2 辅助改进（AI 给候选、人验证应用）→ L3 程序化自我改进（机制固定）→ L4 有界递归（限定领域内改写自身机制）→ L5 通用递归（跨领域迁移）；关键区分不在能不能"建议"改进，而在能否提出、应用、验证并最终修订改进机制。Last AI Built by Humans 五级：改进执行自主 / 改进策略自主 / 经验获取自主 / 环境适应自主 / 递归元改进。用法：先用第一套定位"辅助 / 固定循环 / 机制递归"，再用第二套查系统控制了哪些决策；不因某项目被称 L4 就跳过对其具体循环的分析。两者均为研究框架，非行业标准。

### Claim: APO、SkillOpt、RRSI 主体大多落在 L3——改进机制由人设计，方法名带 self-improvement 不能代替"运行时是否持久修改了改进机制"的检查

- **来源**：[[RSI系列00：递归自我改进总览]]
- **首次出现**：2026-10-21
- **最近更新**：2026-10-24
- **置信度**：0.65
- **状态**：active

> 三者都在冻结模型之外做文本 / harness 空间优化：APO 优化 prompt（textual gradient + beam search + bandit）；SkillOpt 优化 skill 文档（有预算的增删改 + 验证门控，被否决编辑作负面证据）；Google RRSI 优化更广的 harness（prompt、控制流、工具、记忆、上下文管理），同时约束候选的提出与选择。它们的反思提示词、编辑规则、接受门控都由人设计，按阿里分级属 L3，适合用来学"如何建立可靠的改进循环"。作者判断，置信度留中。

### Claim: RRSI 把 harness 自我改进的过拟合拆成三种耦合行为，用正则化约束搜索——优化集提升能否带到陌生任务才是核心问题

- **来源**：[[RSI系列00：递归自我改进总览]]
- **首次出现**：2026-10-21
- **最近更新**：2026-10-24
- **置信度**：0.7
- **状态**：active

> 三种过拟合：编码 benchmark 特定模式、追逐评估噪声、累积不改善底层机制的复杂度。对应约束：编辑预算随轮次退火、保留搜索历史用于归因与引导探索、筛查 benchmark 特定修改、拒绝被噪声抬高或成本过高的改进、剪掉无贡献组件。论文报告演化集最高 +14.1 分、五个分布外 benchmark 最高 +4.7 分，产出 harness 比无正则演化少用约 30% policy token。演化集与分布外的差距本身就说明"优化集越来越好"不等于能力提升。数字来自论文自报，未复现。

### Claim: 判断 RSI 主张的五个验证问题——反馈真不真、是否偶然高分、验证集是否已参与搜索、收益来自能力还是更多计算、有没有损害旧能力

- **来源**：[[RSI系列00：递归自我改进总览]]
- **首次出现**：2026-10-21
- **最近更新**：2026-10-24
- **置信度**：0.75
- **状态**：active

> ① 报告流畅 ≠ 计算正确，能用对账、测试、约束检查的尽量用；② 随机性会制造"最佳版本"，关键比较要重复运行并报波动（即 [[skillopt]] 门控分辨率要算的 σ）；③ 优化器反复依据同一验证集接受修改，该集合就间接参与了搜索，必须留未参与选择的测试集，最好再加分布外任务；④ 多调几次模型、多搜几个候选也能提高成功率，须报告调用数、token、时延与优化阶段总成本；⑤ 修好一个失败场景不代表总体变好，需回归任务。递归层面再加一项：**改进后的优化器与原优化器，在相同起点、相同预算、独立任务上，谁能产生更好的后继系统**——这才是在测"更善于改进"，而不是"某个最终版本分数更高"。

### Claim: 价值越来越多来自"怎样挑选改进"而非"怎样生成改进"——同时设计执行路径与改进路径，先检验外部能力层再决定是否训权重

- **来源**：[[RSI系列00：递归自我改进总览]]
- **首次出现**：2026-10-21
- **最近更新**：2026-10-24
- **置信度**：0.6
- **状态**：active

> 候选生成越来越便宜之后，决定系统能否真正积累能力的是：如何判断改动值得接受、如何保留负面经验、如何发现瓶颈已从 prompt 转到数据或模型、如何衡量单位预算的提升——RRSI 的正则化与 SkillOpt 的门控都在这一侧下功夫（与 [[generation-evaluation-separation]] 同向）。执行路径交付当前任务，改进路径把轨迹转成经过验证的持久更新；日志只有关联到任务结果、修改版本和成本时才是学习资源，须从一开始做进 trace 结构。失败若来自步骤遗漏、工具理解、上下文组织，先试 skill / harness；信息充分流程合理仍有稳定领域能力缺口，再比较更强模型、微调和蒸馏（与 [[prompt-optimization-maturity-ladder]] L0→L2 同向，是工程顺序建议而非"外部 skill 必然优于训练"）。作者有条件的方向判断。

### Claim: RSI 不必动权重——三层学习位置 × 三层搜索位置的正交坐标，Dream-RSI 是"在搜索的第三层上做学习的第三层"

- **来源**：[[2026-09-22-Dream-RSI]]
- **首次出现**：2026-09-22
- **最近更新**：2026-09-25
- **置信度**：0.6
- **状态**：active

> 递归自我改进（RSI）的成立条件被放宽：不必动权重、甚至不训任何网络——**能改自己的探索策略代码、且能可靠评价改动**即成立。三层学习位置：Model 权重（fine-tuning）/ Skill 技能（SkillOpt）/ Search 搜索策略（Dream-RSI）；三层搜索位置：训练时 RL 真搜索 ✅ / 推理时单轨 CoT 非搜索（是摊销搜索——AlphaZero 类比：训练时 MCTS 搜、推理时策略网络一次前向是摊销产物；软回溯 vs 硬回溯、错误 token 留在 context 继续污染条件分布）/ 推理时外层显式编排 ✅（best-of-N→ToT→Dream-RSI）。这个正交坐标把本页既有的 CL-RL 四篇全景与 LifeSkill hybrid 架构放进更大定位图：技能层用完即消失的问题、参数化路径的成本，都是"学习位置"选择的后果。（论文初读，置信度留低）

### Claim: RSI = Recursive Self-Improvement（用改进后的能力再改进自己），不是 recurrent 也不指"递归超级智能"；它是数据飞轮去掉人之后的样子，进内圈的判据是"写得出验证器"

- **来源**：[[FinOps系列02：数据飞轮与RSI]]
- **首次出现**：2026-09-25
- **最近更新**：2026-09-28
- **置信度**：0.7
- **状态**：active

> 术语澄清："recursively self-improving superintelligence"是 intelligence explosion 讨论里的说法，其中 RSI 仍指过程非结果；工程含义以 Dream-RSI 为参照（探索 → 历史变 replay simulator → dreaming 选更好探索策略）。与 [[data-flywheel]] 的三维对照：人在不在环里（飞轮默认在，RSI 目标不在——agent 用自身轨迹当 replay simulator）、积累的是什么（飞轮积累数据与资本，RSI 积累能力本身：skill / 搜索策略 / prompt 配方，[[skillopt]] `best_skill.md` 即其形态，所以 RSI 比飞轮"轻"）、时间常数（季度 vs 小时/天，差两三个量级故可嵌套）。RSI 在 replay 中比较策略优劣几乎只能建立在 RLVR 式可验证信号上——主观分（LLM judge）在离线回放里无法重新获得——所以"哪些任务能进内圈"= "哪些任务写得出验证器"，反直觉地恰是 Too bad to be useful 那一栏（[[cost-per-task]]）。安全阀：cost per task 直接当 RSI 目标会 Goodhart，评估门控须独立于优化目标。待深入：L2→RSI 是否有类似 30~50/100+ 条的数据阈值或取决于 replay coverage；人退出环的顺序（标注/评估/决策哪个先退）与本页既有 Claims 需对照。

## 关联概念

- [[continual-self-improving-ai]] — `extends` RSI 在持续学习之上再加一层：被持续改进的不只是模型或 skill，还有改进机制本身
- [[skillopt]] — `uses` SkillOpt 是 skill 层固定机制自我改进（L3）的代表，其门控与有界步长是改进路径的训练纪律
- [[automatic-prompt-optimization]] — `uses` APO 是 prompt 层固定机制自我改进（L3）的代表
- [[data-flywheel]] — `contrasts` 飞轮默认人在环、积累数据与资本、季度级；RSI 目标人不在环、积累能力本身、小时到天级
- [[generation-evaluation-separation]] — `constrains` 评估门控必须独立于优化目标，否则系统可以通过改变计分方式制造提升
- [[harness-engineering]] — `extends` 把 harness（prompt、skill、工具、流程、记忆）作为可被自动改进的对象 $H$
