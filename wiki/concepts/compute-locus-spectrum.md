# Compute Locus Spectrum（计算位置光谱）

## 摘要

计算位置光谱回答一个选型问题：**一段动态画面的计算应该发生在哪里？** 判据是"内容复杂度 × 实时性来源"两个维度，答案落在一条四层光谱上：文档内（SVG，动画预先写死）→ 本地 JS 改文档（D3/ECharts，离散数据更新）→ 本地 JS/GPU 涂像素（Canvas/WebGL，本地实时数据流）→ 云端 GPU 渲染推流（数字人视频流，浏览器退化为显示器）。复杂度每上一个台阶，内容就离"文件"更远一步——SVG 是乐谱、Canvas 是舞台、云端推流是转播。

该框架于 2026-08-26 动态SVG上下篇首次成形（Foundry Voice Live 页面 Inspector 实探），2026-09-07 Blender 系列在独立批次中补齐了光谱的"本地重计算端"（本地 DCC 渲染 1536 帧成片）与跨位面组合形态（云端 viseme 事件驱动本地渲染载体），复核阈值命中后升格建页。与 [[online-learning]] 页内的 storage-locus 判据（学到的知识存哪）同属"位面判据"家族：一个问计算在哪发生，一个问状态在哪持久化。

## Claims

### Claim: 内容复杂度 × 实时性来源决定画面计算发生在哪里——四层光谱各配"内容存在哪/谁计算/实时性来源"判据

- **来源**：[[从Canvas音波球到云端数字人——浏览器动态内容的计算光谱（动态SVG下篇）]]
- **首次出现**：2026-08-26
- **最近更新**：2026-09-12
- **置信度**：0.75
- **状态**：active

> 同一个产品页面（Foundry Voice Live Playground）Inspector 实探挖出的三种动态元素，加上上篇的动态 SVG，构成完整谱系：① **文档自带动画**（动态 SVG）——内容在文件里（几何描述 + 动画声明），浏览器渲染引擎计算，无实时性（动画预排练）；② **本地 JS 改文档**（D3/ECharts）——内容在 DOM 里，JS 改描述浏览器画，实时性来自离散数据更新；③ **本地 JS 涂像素**（音波球、粒子、游戏，Canvas 2D/WebGL）——内容在像素缓冲区每帧重画，JS/GPU 自己当渲染器，实时性来自本地实时数据流（音频振幅、手势）；④ **云端渲染推流**（数字人，WebRTC + `<video>`）——内容根本不在本地、是一路视频，云端 GPU 集群（神经网络）计算，本地只解码。选型口诀：动画能提前写死 → SVG（单文件、可 git diff、LLM 可生成）；图形由数据生成、更新离散 → SVG + JS（只活在网页里）；每帧全画面重绘、本地实时数据驱动 → Canvas/WebGL（保存分发即降级为位图）；照片级、生成式内容 → 云端渲染 + 视频流（浏览器只是显示器）。

### Claim: 复杂度每上一个台阶，内容离"文件"更远一步——乐谱/舞台/转播三隐喻

- **来源**：[[从Canvas音波球到云端数字人——浏览器动态内容的计算光谱（动态SVG下篇）]]
- **首次出现**：2026-08-26
- **最近更新**：2026-09-12
- **置信度**：0.75
- **状态**：active

> SVG 是乐谱——内容即文档，谁拿到都能演奏；Canvas 是舞台——文档只搭台，演出全靠 JS 当场表演，散场不留痕（保存"网页"可复演，保存"图"即定格）；数字人连舞台都不要了，直接转播一场云端的演出。这条隐喻链解释了各层的可移植性与可归档性差异：越靠光谱左端，内容越接近"可分发的文件"（可嵌入、可 diff、可离线）；越靠右端，内容越绑定"活的运行时"（会话、算力、网络）。数字人三路线（云端视频合成 / 客户端 3D blendshape / Live2D 纸片人）是第 ④ 层内部的再分层——后两条路线的渲染载体又回到 `<canvas>`（WebGL），与音波球同一原理，只是画的内容从波浪线换成带骨骼的人物模型。

### Claim: 本地 DCC 渲染是光谱的"本地重计算端"实例——像素由渲染器输出、模型负责规划操作修正

- **来源**：[[Blender系列01：为什么是Blender——GPT-6-astra发布演示的3D工具选型与Unreal Engine对比]]、[[Blender系列03：虎式坦克实战——从一句话需求到8秒开火动画的完整链路与工程解剖]]
- **首次出现**：2026-09-07
- **最近更新**：2026-09-12
- **置信度**：0.7
- **状态**：active

> Blender 系列提供了浏览器之外的独立印证：AI 生成视频的工作流里像素不是模型直接输出的——**像素由渲染器输出，模型负责规划、操作和修正**（用户描述 → AI 写脚本/操作软件 → 布置资产 → 动画镜头 → 渲染 → 检查修改 → 输出）。虎式坦克 192 帧、面试动画 1536 帧全部在本地 EEVEE 渲染（分别约 2 分 39 秒 / 11 分 50 秒），与云端数字人推流恰构成"AI 驱动画面"的光谱两端：前者计算在本地 DCC、产物是可编辑工程 + 可分发视频文件；后者计算在云端 GPU、产物是一路只能观看的实时流。`.blend` 的"可移植播放"原则（动画烘焙成普通关键帧、播放不依赖脚本或 GPT）正是"内容靠近文件端"的收益——同一判据在浏览器域和 DCC 域给出一致的解释。

### Claim: 跨位面组合形态——云端语音 API 的 viseme 事件流驱动本地渲染载体，时间轴是两个位面的耦合接口

- **来源**：[[Blender系列04：人物面试动画实战——47骨骼程序化表演、TTS配音与音量包络口型同步]]、[[从Canvas音波球到云端数字人——浏览器动态内容的计算光谱（动态SVG下篇）]]
- **首次出现**：2026-09-07
- **最近更新**：2026-09-12
- **置信度**：0.7
- **状态**：active

> 光谱不只有"纯本地"和"纯云端"两类：Azure Speech 的 viseme 路线是**声音在云端合成、画面在本地渲染**的跨位面组合——55 项面部系数按 60 FPS 从云端事件流输出，驱动本地渲染载体（three.js blendshape、Live2D 部件、或 Blender 形态键 60FPS→24fps 时间换算）。耦合接口是时间轴：事件时间用 100 纳秒 tick、必须与最终音频同一时间映射，**不能用网络回调到达时间当动画时间**（事件在音频数据可用时触发，可能远早于播放）。这类组合的判据仍是同一条：哪部分内容复杂度高、实时性来自哪里，哪部分计算就落在对应位面——语音合成（生成式、重算力）留云端，形变渲染（结构已知、轻计算）留本地。

- 2026-09-12：Blender 系列01/03/04（独立新批次）命中复核阈值——本地 DCC 渲染补齐光谱左端、viseme 路线提供跨位面组合形态，用户裁决升格建页。voice-live-agent 页的三路线 Claim 保留（该页视角是 avatar 选型），本页收判据框架本身。
