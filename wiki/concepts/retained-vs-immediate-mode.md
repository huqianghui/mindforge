# Retained Mode vs Immediate Mode（保留模式 vs 立即模式）

## 摘要

图形渲染的两种基本模式。**保留模式**（retained mode）由系统记住"画了什么"：SVG 的每个圆、每条线都是一个 DOM 节点，改一个属性浏览器就知道哪个元素变了。**立即模式**（immediate mode）只留下画出来的像素：Canvas 执行完 `ctx.arc()` 后浏览器并不记得那里有一个圆，要变化就擦掉整块画布、按新数据重画。

这一个区别推出了 SVG 与 Canvas 在动画方式、交互命中、元素规模、清晰度、离开网页能否显示这五方面的差别，也是在网页里选择动态画面技术的根据。它还多出一个和 AI 协作相关的维度：保留模式的产物是 AI 能读能改的文本，立即模式的产物只有像素。

## Claims

### Claim: 保留模式记住图形、立即模式只记住像素——由此推出动画、交互、规模、清晰度、可携带性五项差别

- **来源**：[[Canvas实践：从数字人到知识图谱]]、[[浏览器动态内容的计算光谱]]、[[动态SVG全景]]
- **首次出现**：2026-08-26
- **最近更新**：2026-11-04
- **置信度**：0.8
- **状态**：active

> ① 动画：SVG 改属性即可；Canvas 每帧擦掉重算重画，靠 `requestAnimationFrame` 约 60 次 / 秒。② 交互：SVG 元素自带 hover / click；Canvas 只知道点了哪个像素，点中谁要自己算（常用"影子画布"——每个对象画成独一无二的颜色，按鼠标位置读像素反查）。③ 规模：SVG 每个图形是一个 DOM 节点，几千个同时动就卡；Canvas 画一百个点与几万个点都是重画同一块画布，开销稳定，"整个画面每帧都变"时没有 DOM diff 开销。④ 清晰度：SVG 矢量放大不糊；Canvas 是位图，高分屏要按 2 倍分辨率画。⑤ 可携带性：SVG 能存成文件进文章、PPT、GitHub；Canvas 离开运行 JS 的页面就是空白，只能导出 PNG 或录视频。WebGL / WebGPU 也画在 `<canvas>` 上，只是 `getContext()` 换了更强的画笔。三篇独立定义、浏览器标准行为可核对。

### Claim: 选择顺序看画面跟着什么变——只跟状态变用 CSS / SVG，跟实时数据每帧变才上 Canvas，元素极多或 3D 再上 WebGL

- **来源**：[[Canvas实践：从数字人到知识图谱]]、[[SVG实践：我和AI之间的视觉语言]]
- **首次出现**：2026-11-01
- **最近更新**：2026-11-04
- **置信度**：0.7
- **状态**：active

> 音波球只区分"在听 / 在说"时 CSS 动画就够，浏览器自己播、JS 不用每帧参与；要让波形跟着真实音量起伏，就要每帧读 Web Audio 音量、每帧重画，这时才需要 Canvas（代价：JS 每秒约 60 次 + 远端 WebRTC 音频接入 Web Audio 多一条链路；不显示时 `cancelAnimationFrame` 停掉）。实践样本：演进页几百个点、每个都要响应鼠标、样式要与页面 CSS 一致 → SVG；知识图谱 150 节点 527 关系的力导向布局、还会增长 → Canvas 图谱库；地图与 3D 地标 → WebGL。只分析画面（黑屏检测、取色、截帧）用一块不显示的离屏 Canvas 读像素。

### Claim: 立即模式在数字人里的用法是"读画面"而不是"画画面"——连接层指标看不出帧里是什么，只能读像素

- **来源**：[[Canvas实践：从数字人到知识图谱]]
- **首次出现**：2026-11-01
- **最近更新**：2026-11-04
- **置信度**：0.7
- **状态**：active

> 数字人是服务端渲染的视频，经 WebRTC 由 `<video>` 播放；Canvas 是一块不挂到页面上的画布，用来抽帧读像素。实测案例：解码帧数在涨、字节在流、连接未断，画面却全黑——"有帧在到"不等于"画面正常"，自动恢复没有触发。做法：每秒把帧缩到 32×18 读平均亮度，≤ 8 记空帧、连续 3 次判定失效切备用画面（先缩小读几乎无开销、不逐帧抽以免与解码抢主线程、只判"空不空"不判"够不够亮"所以阈值不随数字人调）。同一手法用于取背景色（边缘列中位数，抵消 H.264 4:2:0 色偏）与缓存静态肖像（存前必须先过黑屏检测）。WebRTC 视频流不会污染画布，跨域图片会。实操验证。

### Claim: 保留模式对 AI 友好、立即模式对 AI 不友好——SVG 是 AI 能读能改、能 diff 的文本，Canvas 在 DOM 里只是空标签

- **来源**：[[SVG实践：我和AI之间的视觉语言]]、[[Canvas实践：从数字人到知识图谱]]
- **首次出现**：2026-11-01
- **最近更新**：2026-11-04
- **置信度**：0.7
- **状态**：active

> SVG 对人是图、对 AI 是文本：坐标写在 `<rect x y>`、`<path d>` 里，AI 读得懂改得动，人用 `git diff` 逐行审——"我看图提意见，AI 改文本，两边改同一个文件"。反向缺口：AI 写 SVG 时看不到渲染结果，中文字宽、字体替换、`text-anchor` 会让估算偏差，所以每张图写完先 `rsvg-convert` 成 PNG 让 AI 看图核对。Canvas 画出来只有像素，Computer Use / Browser Use 碰到 Canvas 页读不到结构只能退回截图识别；对策是把读像素与判断逻辑分开，判断写成吃像素数组的纯函数，不起画布、不接视频流就能单测。

### Claim: 不能跑 JS 的环境只剩保留模式的声明式动画——GitHub README 与 PPT 的两种处理

- **来源**：[[SVG实践：我和AI之间的视觉语言]]、[[Canvas实践：从数字人到知识图谱]]
- **首次出现**：2026-11-01
- **最近更新**：2026-11-04
- **置信度**：0.7
- **状态**：active

> GitHub 显示 README 时去掉 JS，Canvas 图谱是空白——把坐标提前算好写进 SVG，"镜头巡游"用 SMIL `<animate>` 实现（约 120 KB、66 个动画元素），外包链接跳到可交互版本。PowerPoint / Keynote 插入 SVG 只显示静态图形，SMIL 与 CSS 动画都不播：静态图按 2 倍分辨率转 PNG；动画逐帧渲染成 MP4（暂停全部动画、按帧设时间后截图，见 [[clock-driven-rendering]]）。只用 SMIL 与 CSS、不写 JS 的动态 SVG 在 Obsidian 与 GitHub 上都能直接播放。
