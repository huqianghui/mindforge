# 题库：具身智能

配合 [[embodied-intelligence]] 使用，按站点分组。题型：**场景**（给一个情境，说出你会怎么判断）、**辨析**（一句常见说法，判断对错并说出为什么）、**解释**（用自己的话讲清一个机制）。答案是参考要点，说出主要意思即可。

## 第 1 站 · 全景：具身智能是软件 agent 的物理版

### Q1 · 解释

**问**：具身智能和软件 agent 的工程问题大多能一一对应，举三组对应，并说出所有差异的共同根源。

**答**：例如 LLM 对应 VLA（动作是一种模态，但连续、高频、错了不能撤销）；function calling 对应技能原语（成功率不是 100%，要闭环纠错）；RAG 知识库对应 3D 语义地图或世界模型；eval 沙箱对应仿真或视频世界模型（有 sim-to-real gap）；Guardrails 对应 bounded autonomy。共同根源是物理世界不可回滚、连续、有噪声、代价高。

**出处**：[[embodied-ai]]（Claim「具身智能的大部分工程问题在软件 Agent 里都有同构版本」）

### Q2 · 场景

**问**：一个机器人任务要连续做 20 步，每步成功率 95%。团队想继续把单步成功率往上提。你会提醒什么？

**答**：0.95 的 20 次方约 36%，长链条的错误会累积。比起继续抠单步成功率，异常检测与恢复更重要：能发现自己做错并恢复，整体成功率才上得去。

**出处**：[[embodied-ai]]（Claim「具身智能的大部分工程问题在软件 Agent 里都有同构版本」）

### Q3 · 辨析

**问**："人形机器人关注度最高，所以它是最接近商用的形态。"对吗？

**答**：不对。形态越"无聊"越赚钱：边界清楚的 AGV、工业臂、扫地机已经规模商用，轮式双臂是当前工业落地最务实的形态；人形关注最高但离商用最远，人形是形态不是能力。

**出处**：[[embodied-ai]]（Claim「机器人形态越无聊越赚钱」）

### Q4 · 解释

**问**：为什么说机器人形态的选择本质上是数据策略的选择？

**答**：形态锁死了数据能否复用：换一种形态，最贵的数据资产（遥操作轨迹等）基本作废，所以大家在乎跨形态迁移。生态五层里数据层是最深的护城河。

**出处**：[[embodied-ai]]（Claim「机器人形态越无聊越赚钱」）

## 第 2 站 · 系统层：分层多频率控制回路

### Q5 · 解释

**问**：软件 agent 的一个 while 循环，到了具身系统里变成什么样？各层大概多少频率？

**答**：被物理时间拆成三层嵌套：任务层 0.1–1Hz（最像软件 loop）、策略层 10–50Hz（VLA 或扩散策略）、控制层 100–1000Hz（经典控制器，通常没有模型），外加绕开模型的独立安全监视器。频率由该层对付的物理过程时间尺度决定，相邻层大约差 10 倍。

**出处**：[[agent-loop-architecture]]（Claim「agent loop 的物理域实例化」）

### Q6 · 辨析

**问**："具身 agent 和 coding agent 一样，模型自己判断任务完成就可以结束循环。"对吗？

**答**：不对。软件 loop 是模型自宣告结束；具身 loop 的结束信号来自外部验证。五个分野里另外几条是：实时异步而不是回合制、概率性技能而不是确定性工具、安全层独立于模型。

**出处**：[[agent-loop-architecture]]（Claim「agent loop 的物理域实例化」）

### Q7 · 解释

**问**：bounded autonomy 在物理世界的落地顺序是什么？它对应软件 agent 的什么？

**答**：先做信息理解与分析建议，再保留人工审核，最后在明确边界内自动执行。这和软件 agent 的权限模型 read-only → approval → auto-accept 同构。原因是物理世界里幻觉的代价是碰撞和损坏。

**出处**：[[embodied-ai]]（Claim「物理世界的落地形态普遍是 bounded autonomy」）、[[cybernetics-agent-design]]

### Q8 · 辨析

**问**："L4 自动驾驶最难的是开得比人好。"对吗？

**答**：不对。L4 真正难的是 ODD 边界上的安全退出，也就是"知道自己不知道"：感知置信度低于阈值时主动降级、fallback 或执行 Minimal Risk Maneuver。SAE 分级是责任坐标系而不是智能坐标系，L2 到 L3 的跳变是责任转移。

**出处**：[[embodied-ai]]（Claim「物理世界的落地形态普遍是 bounded autonomy」）

## 第 3 站 · 空间层：重建管状态，世界模型管状态转移

### Q9 · 场景

**问**：家里装了摄像头，机器人融合出一张标好"沙发在哪、门开没开"的 3D 语义地图。有人说这就是世界模型。你怎么判断？

**答**：这是重建层，回答"世界现在什么样"。在这张地图上预测"猫下一秒往哪跑、路径两秒后会不会被人挡住"才是世界模型层，回答"动作之下会怎么变"。重建层管状态，世界模型层管状态转移。

**出处**：[[spatial-intelligence]]（Claim「空间智能分层栈」）

### Q10 · 辨析

**问**："用 3DGS 把房间重建出来，机器人就有空间记忆了。"对吗？

**答**：不对。3DGS 负责把几何存下并重现，只处理"现在"。从几何到记忆还隔着两层：先加语义（对象、位姿、关系的 3D 语义地图），再加时间与生命周期。Spatial Memory 不是一张地图，而是一个可查询、可更新的 3D + 语义 + 时间数据库。

**出处**：[[spatial-intelligence]]（Claim「从几何到记忆隔着两层」）

### Q11 · 场景

**问**：做一款扫地机器人，团队想上 3DGS 做高保真重建。你的建议？

**答**：需要 XYZ 才建显式 3D，而且建到需求对应的那一层为止。扫地机一张 occupancy grid 就够，不需要几百万个 Gaussian；3DGS 是给高保真自由视角渲染用的。

**出处**：[[spatial-intelligence]]（Claim「选用边界」）

### Q12 · 解释

**问**：神经 3D 生成的开源版图分哪三层？哪类需求仍然要走 agent 加传统工具？

**答**：场景生成铺环境（如 HY-World 2.0）、资产生成出道具（如 TRELLIS.2）、agent 操作引擎组装规则与物理（Blender、UE5）。"可参数化编辑的工程资产"仍归 agent 加传统工具路线，因为生成模型不编码部件级语义。

**出处**：[[spatial-intelligence]]（Claim「神经 3D 生成的开源版图是三层分工」）

## 第 4 站 · 认知层：世界模型是一个角色

### Q13 · 辨析

**问**："世界模型是一种特定的网络架构，比如视频生成模型。"对吗？

**答**：不对。世界模型是角色不是架构，用"回答什么问题"定义：给定状态和动作，预测下一个状态 P(s′|s,a)。同一个 Diffusion Transformer，输入历史帧加动作、输出未来帧是世界模型；输入当前帧加指令、输出动作块就是策略。实现路线有像素、潜空间、显式 3D、物理方程四种。

**出处**：[[world-model]]（Claim「世界模型是角色不是架构」）

### Q14 · 场景

**问**：有人问特斯拉 FSD 算不算世界模型。你按什么标准判断？

**答**：看三要素：Representation、action-conditioned Prediction、Planning。传感器构成、是否端到端、生不生成视频都不是标准。FSD 是光谱问题：高度端到端的视觉驾驶策略加上强世界表征，缺的一环证据是显式的动作条件动力学学习与 rollout。这个归类基于公开材料推断，不是官方确认。

**出处**：[[world-model]]（Claim「判别世界模型看三要素」）

### Q15 · 解释

**问**：世界模型和策略、评估器、时间序列预测分别怎么区分？

**答**：和策略比，条件里有没有目标：策略要完成什么，世界模型对任务中立。和评估器比，世界模型预测后果但不评判好坏，Dreamer 的 reward head 是叠加上去的评估角色。和时间序列预测比，条件里有没有"我"的动作：建模了自己下单对市场的冲击才是世界模型。

**出处**：[[world-model]]（Claim「与策略/评估器/时间序列预测的三条分界线」）

### Q16 · 解释

**问**：为什么说 LLM 再大也补不上"动作之后世界怎么变"？

**答**：Moravec 悖论的三层原因：感知运动被打磨了几亿年，已内化为本能，写不出规则；文本是人替机器压缩好的离散符号，物理世界是连续高维带噪的场，带"动作 → 后果"标注的数据极少；文本答错可重写，动作做错不能回滚，评判来自又贵又慢的物理后果。LLM 学的东西里缺动力学，世界模型补的正是这一块。

**出处**：[[world-model]]（Claim「Moravec 悖论说明 LLM 缺的是动作之后世界怎么变」）

## 第 5 站 · 世界模型的路线、交汇与风险

### Q17 · 辨析

**问**："世界模型和 LLM 的区别是世界模型不是自回归的。"对吗？

**答**：不对，是否自回归不是分界线。LLM 回答"接下来最可能说什么"，世界模型回答"如果我这么做，世界会变成什么样"。V-JEPA 2 与 Qwen3-VL 的对照把它说得更准：分野在预测放在训练目标的哪个位置，前者把预测未来表征直接写进 objective、接口是 latent、消费者是高频调用的规划器。

**出处**：[[world-model]]（Claim「与 LLM 的分野不在生成机制而在要回答的问题」）

### Q18 · 场景

**问**：团队要为机器人策略训练准备大量逼真的合成数据，另一个团队要在机器人上做高频规划。两边各选哪条世界模型路线？

**答**：要海量逼真数据选像素路线，它的产品是"可看的世界"，视频能给别的模型当训练语料；要高频规划选潜空间路线，它的产品是"可规划的状态"。要可读的物理量则选显式 3D 或物理方程。选路线先问"我需要它输出什么"。

**出处**：[[world-model]]（Claim「像素路线与潜空间路线是用途分工不是优劣」、Claim「看路线分三层」）

### Q19 · 解释

**问**：显式 3D 路线和 latent 路线在空间一致性上有什么不同？

**答**：显式路线的一致性由表示本身保证；latent 路线的空间一致性是统计能力，没有 metric 精度承诺，有空间理解但没有 XYZ。产品上常用 Hybrid：显式几何管"在哪里"，学习到的动力学管"接下来会怎样"。

**出处**：[[world-model]]（Claim「显式路线的一致性由表示本身保证」）

### Q20 · 场景

**问**：一个世界模型生成的画面看起来完全合理，团队想直接把它的规划结果下发到机械臂。你会担心什么？

**答**：物理世界的幻觉更贵且不会自己暴露：估错摩擦系数、低估碰撞，在虚拟里不报错，下发就是撞击。能否进决策回路要看真实闭环里的预测误差；评估器与验证器要和世界模型分开；对策包括边界内自主、绕开模型的安全监视器、关键物理用方程兜底、上真机前回归。画面合理不等于物理正确。

**出处**：[[world-model]]（Claim「物理世界的幻觉更贵且不会自己暴露」）

## 第 6 站 · 方法地基：扩散与 flow matching

### Q21 · 辨析

**问**："扩散模型是一种网络结构。"对吗？

**答**：不对。扩散是一种生成方法（训练目标加生成过程），对网络结构没有要求，训出来的网络才叫扩散模型。训练学的是修正方向场（score），生成是从纯噪声出发的多步小修正。

**出处**：[[diffusion-model]]

### Q22 · 解释

**问**：扩散的选型判据"高维、连续、多峰"分别指什么？哪些场景不该用扩散？

**答**：高维指被生成对象的维度（动作块 50 步 × 7 自由度 = 350 维），不是模型内部维度；连续说的是取值类型，与自回归还是双向无关；多峰是分布形状，同一情境有多个正确答案（绕左绕右都对）。离散决策、低维确定性输出、毫秒级延迟且单峰的场景不该用它。

**出处**：[[diffusion-model]]（Claim「高维/连续/多峰三属性是扩散的选型判据」）

### Q23 · 解释

**问**：扩散和 flow matching 是什么关系？flow matching 换来了什么？

**答**：同一框架的两种参数化，谱系是 DDPM → score-based SDE → flow matching。flow matching 走直线路径、预测速度场、确定性采样，换来更少的步数（π0 十步积分）和可复现。

**出处**：[[diffusion-model]]（Claim「扩散与 flow matching 是同一框架的两种参数化」）

### Q24 · 辨析

**问**："视频世界模型知道向左走会掉坑，说明它做了因果推理。"对吗？

**答**：不对。片段内部整段视频在多步去噪中作为联合分布一起浮现，物理后果是训练数据统计规律的体现；跨片段才有时间上的自回归。模型"知道"会掉是分布拟合，不是因果推理。

**出处**：[[diffusion-model]]（Claim「视频世界模型渲染后果的机制」）

## 第 7 站 · 行动层：VLA 的输出架构

### Q25 · 解释

**问**：VLA 的动作输出为什么从离散 token 转向连续动作头？最本质的原因是哪个？

**答**：四个原因：精度与平滑性、频率与延迟、多峰分布、维度间耦合，其中多峰分布最本质。主流系统仍是分层的：高层任务规划用 VLM 做低频离散决策，低层连续动作头出高频控制信号。

**出处**：[[vision-language-action-model]]（Claim「动作输出从离散 token 转向连续动作头的四个原因」）

### Q26 · 辨析

**问**："π0 的 VLM 和动作专家权重是分开的，所以训练动作不会伤到 VLM 的能力。"对吗？

**答**：不对。两组专家通过共享 self-attention 交互，权重分离不等于梯度隔离，动作损失仍会侵蚀 VLM 主干。Knowledge Insulation 因此而生：梯度隔离加双目标单阶段协同训练。

**出处**：[[vision-language-action-model]]（Claim「π0 证明 VLM 知识可以接到连续控制上」）

### Q27 · 辨析

**问**："离散 token 路线在物理控制里行不通。"对吗？

**答**：说过头了。FAST 用 DCT 加 BPE 做频域压缩后，自回归训练快 5 倍、精度与流匹配相当，说明瓶颈在分词而不在离散本身；代价在推理侧，延迟大 7 倍。π0.5 把两条路线串起来：离散 token 预训练加流匹配后训练。

**出处**：[[vision-language-action-model]]（Claim「FAST 证明离散路线的瓶颈在分词而非离散本身」）

### Q28 · 解释

**问**：Hi Robot 和 π0.5 都做了"慢思考 + 快动作"的分层，区别在哪里？

**答**：Hi Robot 用同一 VLM 底座的两种微调，部署成两个模型（System 2 约 1 秒或收到语言反馈触发，System 1 高频出块）；π0.5 把同样的分层做在同一组权重里。分层是能力结构，不必然是部署结构。

**出处**：[[vision-language-action-model]]（Claim「分层是能力结构，不必然是部署结构」）

## 第 8 站 · 动作块与频率口径

### Q29 · 解释

**问**：动作明明有先后因果，动作块为什么能在块内并行生成？

**答**：真正的因果依赖不在块内而在块间。块内用双向注意力加迭代去噪并行收敛，规划本来就是对一段未来的联合优化；块间执行一部分动作后拿新观测重新规划（receding horizon），由重规划承担因果。

**出处**：[[action-chunking]]（Claim「块内并行去噪 + 块间闭环重规划的分工」）

### Q30 · 解释

**问**：RTC 解决的是什么问题？怎么解决的？

**答**：同步执行时动作块边界必然停顿，而且"停止 - 重启"会带来模型没见过的动力学突变。RTC 把新旧块的衔接变成 inpainting：重叠段冻结为已承诺的动作，之后约束渐弱。推理时版不用重训，只适用于扩散或流匹配策略；延迟超过 300ms 仍稳定。

**出处**：[[action-chunking]]（Claim「RTC 把动作块边界的执行停顿转化为 inpainting」）

### Q31 · 辨析

**问**："π0 动作块生成要 73ms，所以它的控制频率只有 10Hz 出头。"对吗？

**答**：不对，混了口径。73ms 是块生成延迟，换算出的 10Hz 只是最大串行推理调用速率；控制执行频率是 50Hz 级，因为块内动作逐步执行；重规划频率是实验设置（20Hz 平台 16 步重规划约 1.25Hz），不是架构上限。

**出处**：[[action-chunking]]（Claim「三个频率口径必须分开」）

### Q32 · 场景

**问**：一家公司宣布他们的 VLA "在没见过的家里成功率 90%"。你会追问哪些问题？

**答**：至少分开问：是新环境、新物体还是新技能的泛化（三件事）；成功率挂的是什么任务和设置；错误恢复与人工介入率；数据成本（多少小时遥操作、多少个环境）；宣传里的频率是哪个口径。

**出处**：[[vision-language-action-model]]（Claim「评估 VLA 声明的维度清单」）

## 第 9 站 · 落地：数据、自动驾驶与分层选型

### Q33 · 解释

**问**：机器人训练数据有哪三条来源？为什么要组合使用？

**答**：遥操作质量最高、成本也最高；仿真合成规模大但有 sim-to-real gap；人类视频转化（如 VITRA 把人手当成一种末端执行器）走的是"互联网语料"路线。三条和 LLM 的人工标注、合成数据、网络爬取同构，各有短板，只能组合使用。数据策略本身就是技术路线。

**出处**：[[embodied-ai]]（Claim「数据策略本身就是技术路线」）

### Q34 · 辨析

**问**："π0.5 能在没见过的房子里干活，是因为架构更先进。"对吗？

**答**：不对，靠的是数据组合：97.6% 的预训练数据来自非目标平台，环境数从 3 增到 104 时性能单调上升，去掉跨平台数据分布外指令遵循就崩。另外 π0.6 的 RECAP 转向真机经验 RL，但它的"从经验学习"包含人工纠正和离线迭代，不是部署中实时更新。

**出处**：[[vision-language-action-model]]（Claim「π0.5 的开放世界泛化靠数据组合而非架构魔法」）

### Q35 · 解释

**问**：为什么说 L2 量产数据飞轮有一道裂缝？靠什么补？

**答**：L2 量产数据学的是人类驾驶分布，不是"我该怎么开"，两个分布不同。要在中间插入世界模型、仿真加 RL 的环节，再由 L4 运营数据回流。驾驶数据天然自带动作，是训练动作条件世界模型的理想形态，但统计规律不等于因果理解，规划级世界模型要能做反事实推演。

**出处**：[[world-model]]（Claim「自动驾驶与具身智能两条产业线在世界模型层交汇」）

### Q36 · 场景

**问**：客户想"给工厂机械臂加上听懂指令换任务的能力"，并打算用一个开放权重的 3D 世界模型批量生成仿真环境来训练。你怎么建议？

**答**：先定层：入场点由能力级别决定，传统方案、模仿学习（ACT，几十条 demo）、VLA、世界模型逐级升级，触发条件是任务泛化需求和数据量；机械臂先 benchmark 再定模型。再查许可：开放权重不等于随便用，比如 HY-World 2.0 的许可禁止用模型及其输出改进其他 AI 模型，用它批量生成环境训练策略是否落入禁区，上生产前要逐字对照条款。

**出处**：[[embodied-ai]]（Claim「入场点由能力级别决定」、Claim「开放权重 ≠ 随便用」）、[[vision-language-action-model]]（Claim「VLA 选型看场景而非排名」）
